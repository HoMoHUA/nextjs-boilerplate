# تحویل نسخهٔ دفتر و وضعیت انتشار

تاریخ: 2026-10-20، Asia/Tehran. کد اجرایی: `9b7c92b418fc2d8d74275bc48d3a6d48f5482725`، برنچ مستقل `codex/office-studio-upgrade`.

**کد و شواهد در ریپو منتشر شده‌اند؛ استقرار وب هنوز انجام نشده است.** کاربر انتشار آنلاین پس از تکمیل را مجاز کرده، اما این محیط اتصال SSH/حساب سرور یا workflow استقرار ندارد. درخواست HTTPS به `office.arklyn.ir` نیز در tunnel شبکه با ۴۰۳ رد می‌شود. درخواست اطلاعات اتصال ثبت شده است؛ رمز یا کلید خصوصی نباید در چت یا ریپو قرار گیرد.

## خروجی آماده

کاراکتر و اشیای تألیفی، ویرایشگر ظاهر با ذخیره و بازیابی امن، سه LOD و کیفیت تطبیقی، دارک‌مود صحنه و رابط، پایهٔ PWA، حرکت و مسیر رزروشده، قهوه و مصرف رویداد معتبر جلسه در برنچ موجودند. [پوشش فازهای سند](AVATAR_CONTINUATION.fa.md) موارد ساخته‌شده و gateهای باز را جدا ثبت می‌کند.

Low از یک batch با مفصل سخت و نرمال درست استفاده می‌کند. در سناریوی ۱۲ نفره، نمونهٔ تاریخی ۶۳۸ call به حدود ۱۲۱ رسید. نمونه‌برداری نهایی 60.0 ثانیه، median=121, p95=121, max=121 call را ثبت کرد؛ این‌ها تعداد draw call هستند و p95 زمان فریم یا FPS گوشی نیستند. Low نهایی ۲٬۷۴۹ مثلث در بدترین ترکیب محافظه‌کارانه دارد؛ سقف ۳۰۰۰ رعایت شده است.

## اعتبارسنجی

```sh
npm run test:frontend
npm run lint
npm run typecheck
npm run build
```

۲۰ مجموعهٔ تست فرانت و سه بررسی واقعی فایل سه‌بعدی پاس شدند. بررسی‌ها شامل هویت و حفاظت داده، صف تعامل، تمام مسیرها، جلسه‌های متوالی، کیفیت، joint و نرمال زیر تغییر مقیاس، مالکیت منابع، هدف دکمه از GLB و پوشش بالای سر در هر ۹ مدل مو هستند.

مرورگر Chromium/SwiftShader، Save/Cancel و HEX، reload، موبایل، context-loss واقعی و Retry، ماتریس ۱/۶/۱۲، رویداد جلسهٔ mock و تماس ثابت فنجان/دست را گذراند. در سناریوی قطع WebGL تنها خطای عمدیِ context loss ثبت شد؛ آخرین سناریوی ۱۲ نفره خطای JavaScript یا shader ندارد. تست تغییر Low/Medium/High پس از گرم‌شدن سه cache به تعداد منابع ثابت برگشت؛ این، آزمون بلندمدت نشتی یا اندازه‌گیری بایت GPU نیست.

backend در این ارتقا تغییر نکرده است. یک خطای baseline قبلی در `test_sse_exercises_real_child_without_real_claude_prompt` مربوط به دسترسی `/root/.claude/agents` و `permissionMode` ثبت شده؛ نتیجهٔ فرانت به‌عنوان سبز بودن کل backend گزارش نمی‌شود. درخواست واقعی مدل یا پیام Telegram برای آزمون ارسال نشده است.

نسخهٔ مستقل نهایی نیز [smoke-test انتشار](benchmarks/avatar-upgrade/release-smoke.json) را با preview پیش‌فرض ۴۰۴ و حفاظت موقت احراز هویت ۳۰۷/۴۰۱ گذراند. این آزمون محلی است و به معنی استقرار دامنه نیست.

## استقرار پس از فراهم‌شدن اتصال

مقصد از فایل‌های `deploy/runtime` ریپو، `office.arklyn.ir` است؛ این مسیرها باید روی سرور واقعی تأیید شوند. نیازی به تغییر DNS، رمز، Gateway یا broker برای انتشار این frontend نیست.

1. روی سرور، سرویس وب، مسیر فعلی و آخرین commit را بررسی و واحد سرویس و revision قبلی را برای rollback نگه دارید. فایل `/etc/arklyn-office/web.env` و سرویس‌های broker/Gateway دست‌نخورده می‌مانند.
2. commit دقیق بالا را در یک پوشهٔ release جدید آماده کنید؛ build را در پوشه‌ای که سرور فعال از آن فایل می‌خواند اجرا نکنید. وابستگی‌ها با `npm ci` از lockfile نصب شوند و چهار فرمان بررسی بالا اجرا شوند؛ تولید دوبارهٔ مدل‌ها در سرور لازم نیست.
3. `.next/standalone` به‌همراه `public` و `.next/static` بستهٔ مستقل است. candidate را ابتدا روی پورت آزاد و loopback با همان پیکربندی موجود آزمایش کنید؛ `STUDIO_PREVIEW_ENABLED` در نسخهٔ عمومی فعال نشود.
4. پس از سلامت candidate، تنها سرویس وب را به release جدید منتقل و restart کنید. تنظیم WorkingDirectory/ExecStart/cache-writes باید با واحد واقعی سرور سازگار باشد؛ تنظیم پیش‌فرض حدسی روی سرور اعمال نشده است.
5. HTTPS، احراز هویت، manifest/icons، hash مدل‌ها و نمایش صحنه با همان تنظیمات قبلی بررسی شوند. از `deploy/verify.sh --domain office.arklyn.ir --port 3101 --no-agent` فقط پس از تأیید پورت واقعی استفاده کنید؛ فراخوانی زندهٔ مدل جزو smoke-test این انتشار نیست.
6. در خطای candidate یا smoke-test، مسیر سرویس به revision قبلی برگردد و فقط سرویس وب restart شود. rollback پس از سفارشی‌سازی کاربران باید نسخهٔ داده‌خوان سازگار را نگه دارد یا ابتدا از تنظیمات مرورگر نسخهٔ محلی گرفته شود؛ کد قدیمی‌تر از زیرساخت appearance ممکن است فیلدهای تازه را هنگام ذخیره نادیده بگیرد.

برنچ مستقل و commit پایهٔ Office یعنی `b59c04687ecc0e9961d30c143ddf76b2e091810d` حفظ شده‌اند. خاموش‌کردن build-time `NEXT_PUBLIC_AVATAR_V2_ENABLED=false` با rebuild نیز renderer قبلی را برمی‌گرداند و دادهٔ ظاهر V2 را حذف نمی‌کند؛ این فقط rollback کاراکتر است و جای بازگشت کل release را نمی‌گیرد.

## پذیرش‌های باز

producer زندهٔ `planning_meeting` در broker موجود نیست؛ جلسهٔ خودکار زنده با consumer تنها ایجاد نمی‌شود. نصب و FPS روی Android/iOS واقعی، هزینهٔ GPU و High/Medium، آزمون بلندمدت منابع و بازبینی همهٔ ترکیب‌های صورت/لباس/اکسسوری و تماس صندلی/قلم/انگشت/پیچ مسیر همچنان باقی‌اند. این موارد به‌عنوان انجام‌شده یا مانع برطرف‌شدهٔ انتشار گزارش نشده‌اند.
